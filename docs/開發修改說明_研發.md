# 開發／修改說明書（給研發人員）

## 一、環境與啟動

```bash
npm install
npm run dev      # http://localhost:5173（連的是雲端 Supabase，非本機 DB）
npm run build    # tsc -b && vite build（部署前務必無 tsc 錯誤）
npm run lint     # oxlint
```

`.env`：`VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`（本機開發用；正式站由 GitHub Actions secrets 注入）。

> **注意**：本機 dev 也是連正式 Supabase 專案，操作會動到真實資料。測試破壞性操作請小心或另開測試專案。

## 二、分支與部署流程

1. 所有開發在 **`dev`** 分支，`git push origin dev`。
2. 要上正式站時：
   ```bash
   git branch backup-main-YYYYMMDD-N origin/main   # 建回復點
   git push origin backup-main-YYYYMMDD-N
   git checkout main && git merge --ff-only dev
   git push origin main            # 觸發 GitHub Actions 部署
   git checkout dev
   ```
3. 觀察部署：`gh run watch <id>`；成功後正式站即更新（CDN 可能延遲 1～2 分鐘，使用者需 Ctrl+F5）。

> `main` 只在確認要發布時合併，避免把未完成的東西推上線。

## 三、改「前端」功能
- 頁面在 `src/pages/`，共用元件在 `src/components/`，工具在 `src/lib/`。
- 新頁面：在 `App.tsx` 加 `<Route>`，需要權限就用 `<RoleGate roles=...>` 或 `<EngineeringRoute>` 包起來；選單在 `components/AppShell.tsx`。
- 列表頁請沿用「篩選條件卡」與 `<FlashMessage/>`；建立成功後 `navigate('/清單', { state: { flash: 訊息 } })`。

## 四、改「資料庫」（migration）
- 在 `supabase/migrations/` 新增 `YYYYMMDDHHMMSS_描述.sql`。
- **部署方式（手動）**：Supabase Dashboard → **SQL Editor** → 貼上整份 SQL → Run。依時間戳順序執行。
- View 記得 `security_invoker = true`；牽涉扣量的交易函式用 `SECURITY DEFINER` 並 `REVOKE ... FROM anon, authenticated` / `GRANT ... TO service_role`。
- **例外**：自帶權限檢查（`is_admin()`）的函式可直接 `GRANT ... TO authenticated` 由前端 `rpc` 呼叫（如 `stock_adjust`/`stock_adjust_delete`），省去 Edge Function。

## 五、改「Edge Function」
- 每支在 `supabase/functions/<名稱>/index.ts`，**必須單檔自足**（Dashboard 編輯器不解析 `../_shared/*` 相對匯入）。
- **部署方式（手動）**：Dashboard → **Edge Functions** → 選該函式 → Editor → 整份貼上 → Deploy。
- 手動貼上容易漏（貼錯區、沒存到），部署後務必實測一次。
- supabase-js 的 `functions.invoke()` 會吞掉非 2xx 的錯誤內容 → 前端請用 `lib/functionError.ts` 的 `functionErrorMessage()` 還原真正訊息；或函式一律回 HTTP 200 + `{success:false,message}`。

## 六、圖片命名重點
- **Storage 鍵只能 ASCII**（中文會 400 InvalidKey）。
- 中文命名（`種類-名稱-規格-數量單位-日期序號`）以「下載檔名」呈現：`getPublicUrl(path, { download })`。
- 相關函式都在 `lib/imageUpload.ts`：`uploadItemPhoto`（入庫）、`attachAiPhotoToItem`（AI 確認後搬照片）、`uploadReplacementPhoto`（編輯換圖）、`itemPhotoDownloadName/Url`。

## 七、機密金鑰
- 一律由管理員在後台輸入（AI 金鑰→`ai_stock_in_settings`；LINE→`line_notification_settings`），**不寫進前端、不進 git**。
- 若不慎外洩（貼到聊天、commit），立即在來源端作廢重發。

## 八、常見雷點
| 症狀 | 原因/解法 |
|---|---|
| 深連結重新整理 404 | 必須用 HashRouter（已設定） |
| Edge Function 改了沒生效 | 手動重部署沒成功；改法可考慮移到前端（如 AI 照片搬移） |
| 列表某欄在寬螢幕撐出大空隙 | 短欄位加 `className="col-min"`（`width:1%;white-space:nowrap`） |
| 圖片上傳失敗 InvalidKey | 鍵含非 ASCII；用 `sanitizeForFileName` |
| View 看得到不該看的資料 | 忘了 `security_invoker = true` |
