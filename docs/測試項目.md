# 自動化測試項目清單（供 GitHub Actions 使用）

分三層：**A 靜態關卡**（免後端，永遠可跑）、**B 單元測試**（純函式，免後端）、
**C E2E 流程**（需一個「測試用 Supabase 專案 + 種子資料」，用 Playwright 分角色跑）。

建議工具：型別/lint/build 已有；單元測試 **Vitest**；E2E **Playwright**。
CI 建議：A、B 每次 push 都跑；C 需要測試專案的 URL/anon key（放 Actions secrets），
以獨立 job（或 nightly）跑，避免污染正式資料。

帳號建議（種子）：`admin/admin`（總管）、一個幫主（綁某據點）、一個小幫手（綁某據點）。

## C. E2E 流程（需測試用 Supabase + 種子；Playwright）

### C1 登入與權限
- C1-1 正確帳密登入成功、導向戰情總覽。
- C1-2 錯誤密碼顯示「帳號或密碼錯誤」（不透露帳號是否存在）。
- C1-3 未登入存取任何頁 → 導向 `/login`。
- C1-4 選單項目依角色正確：
  - 小幫手：物資管理只有「物資領用」；紀錄查詢只有「個人領用紀錄」；無系統管理。
  - 幫主：物資管理有 入庫/領用/轉移/AI；紀錄有 領用/報廢/轉移；系統管理只有物資明細。
  - 總管：全部項目（含帳號/據點/庫存種類/LINE/AI 設定/操作紀錄/分析/捐贈）。
- C1-5 路由守衛：小幫手直接打 `/supply-items`、`/stock-in`、`/transfers`、`/item-ledger`、`/disposals`、`/admin/*` → 被擋（無權限畫面/導回）。
- C1-6 登入、登出各寫入一筆 `activity_log`（category=登入）。

### C2 戰情總覽（全域一致）
- C2-1 四張卡片顯示數字；點卡片進對應狀態清單頁。
- C2-2 各據點統計：正常/低庫存 N/即將過期 N 徽章正確。
- C2-3 **全角色數字一致**：小幫手、幫主看到的卡片與各據點狀態＝總管（同一份全域資料）。
- C2-4 「查看物資」按鈕僅總管出現；其他角色顯示「—」。
- C2-5 待處理需求面板：核准報廢/完成/取消（總管）、轉移補貨（總管+幫主）按角色顯示與運作。

### C3 狀態清單
- C3-1 低庫存/即期/已過期/總量不足 各清單內容正確（跨全部據點）。
- C3-2 舉手：總管、幫主可；小幫手一律「—」。
- C3-3 幫主的舉手/申請報廢只在**自己據點**的列出現；別據點列顯示「—」；總量不足列可為自己據點舉手。
- C3-4 已過期：總管「報廢」連到報廢頁帶批次；幫主「申請報廢」寫 `supply_request`(type=disposal)。
- C3-5 募資觸發點顯示與清單以「門檻 × 0.9」判定。
- C3-6 舉手/申請報廢寫入 `activity_log`（category=申請）。

### C4 物資入庫
- C4-1 多品項：新增品項/移除品項；至少保留一筆。
- C4-2 送出前確認視窗列出**全部品項**與數量。
- C4-3 規格可選「無（未指定）」先入庫。
- C4-4 有效期限為日曆選擇；無效期物資不需填。
- C4-5 捐贈人（姓名/電話/地址）共用套用到全部品項。
- C4-6 入庫後：庫存增加、寫 `supply_stock_in_log`、寫 `activity_log`（庫存異動）。

### C5 物資管理（物資清單，總管）
- C5-1 篩選：關鍵字/狀態(低庫存/即期/總量不足/過期)/據點/種類。
- C5-2 「安全庫存」欄＝庫存種類設定的據點門檻（與設定一致，非快照）。
- C5-3 編輯：安全庫存唯讀；可補規格（自動帶入分類）。
- C5-4 在庫存種類設定改據點門檻後，物資清單安全庫存欄與低庫存狀態同步變化。
- C5-5 刪除物資（軟刪除）；匯出 Excel 底部有「總計」數量列。
- C5-6 編輯/刪除寫入 `activity_log`（資料維護）。

### C6 物資領用
- C6-1 多人多品項一張單送出；庫存扣除；寫 log。
- C6-2 非總管只能選自己據點的品項（切換據點清空清單）。
- C6-3 小幫手 5 個工作天內可修改自己上傳的領用；逾時或他人不可。總管不限。
- C6-4 修改/取消會回算庫存。
- C6-5 詳情視窗、列印領用單。
- C6-6 領用/修改/取消寫入 `activity_log`。
- C6-7 領用紀錄頁：小幫手只看自己（標題「個人領用紀錄」）；據點篩選只列使用中據點；日期區間；匯出含總計。

### C7 物資轉移
- C7-1 建立轉移：立即扣來源庫存、產生 Pending。
- C7-2 目的據點「確認送達」→ 入庫目的；「取消」→ 退回來源。
- C7-3 來源＝目的擋掉。
- C7-4 建立/確認/取消寫入 `activity_log`。

### C8 物資報廢
- C8-1 建立報廢：扣庫存、寫 `supply_disposal_log`、寫 `activity_log`。
- C8-2 「報廢紀錄」頁：幫主看不到「新增報廢」按鈕（僅總管）。
- C8-3 已過期清單帶入報廢（帶 supplyItemId）。

### C9 AI 智慧入庫
- C9-1 一張照片/一段文字含多項 → 顯示多筆品項卡片，逐項可編輯/移除。
- C9-2 辨識前後顯示照片。
- C9-3 版面對齊物資入庫（步驟卡片、信心徽章、日曆）。
- C9-4 確認後：各品項入庫、照片搬到 items（多品項共用同張）、寫 `activity_log`。
- C9-5 手機影像入庫同樣支援多品項與照片預覽。
- （辨識 API 可用 mock provider，避免 CI 花費真金鑰。）

### C10 紀錄查詢與分析
- C10-1 領用/捐贈/報廢/轉移/AI 各紀錄頁：篩選 + 日期區間 + 匯出（底部總計）。
- C10-2 捐贈紀錄：補登/編輯/刪除捐贈人（不影響庫存），寫 `activity_log`。
- C10-3 領取分析/捐贈分析（總管）樞紐與物流追蹤顯示、可匯出。

### C11 系統管理
- C11-1 帳號管理：新增/修改/停用；**不能停用最後一個總管**、**不能停用自己**；寫 `activity_log`。
- C11-2 據點管理：新增/修改/停用；停用據點不再出現在領用等篩選；寫 `activity_log`。
- C11-3 庫存種類設定：新增規格、設定據點門檻、總量門檻；觸發點顯示「門檻 × 0.9」；寫 `activity_log`。
- C11-4 LINE/AI 設定：儲存成功；金鑰留空表示不變更；寫 `activity_log`。
- C11-5 操作紀錄（activity_log）頁：僅總管可見；關鍵字/分類/據點/日期區間 篩選；細節視窗；匯出 Excel。
- C11-6 抽查：上面各操作在操作紀錄頁都能查到對應的一筆。

### C12 資料層 / RLS（可用 supabase-js 直接打 API 測）
- C12-1 `supply_item`：任何登入者可 SELECT 全部據點；非總管 UPDATE/DELETE 別據點被 RLS 擋。
- C12-2 `activity_log`：SELECT 僅總管；INSERT 只能寫 `actor_id = auth.uid()` 的列。
- C12-3 `dashboard_location_status` / `dashboard_summary`：不同角色查詢得到**相同**全域數字。
- C12-4 扣庫存交易（領用/轉移/報廢）由 Edge Function 服務端把關：非所屬據點呼叫被拒。

### C13 手機 / LINE（多需真實 LINE/LIFF，建議標為手動或半自動）
- C13-1 手機頁面：物資查詢/領用/轉讓/影像入庫 全螢幕可用。
- C13-2 LINE 綁定流程、被動通知（低庫存/即期/過期、去重複）— 建議手動驗證。

## 建議 GitHub Actions 結構（示意）
- **job: static**（每次 push）：`npm ci` → `tsc --noEmit` → `npm run lint` → `npm run build`。
- **job: unit**（每次 push）：`npm ci` → `npm run test`（Vitest，跑 B 區）。
- **job: e2e**（手動/nightly，需 secrets：`TEST_SUPABASE_URL`/`TEST_SUPABASE_ANON_KEY` 指向測試專案）：
  種子資料 → `npx playwright test`（跑 C 區，分角色）。**不要對正式專案跑。**
