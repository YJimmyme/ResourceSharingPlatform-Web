# 資料庫、資料流與功能對應

## 一、資料表

| 資料表 | 用途 | 重點欄位 |
|---|---|---|
| `profiles` | 使用者（對應 `auth.users`） | `username`, `role_name`(Admin/Cadre/SocialWorker), `location_id`, `display_name`, `is_active` |
| `supply_location` | 據點 | `location_name`, `address`, `phone`, `contact_person`, `latitude`, `longitude` |
| `inventory_item_definition` | 目錄主檔（種類/名稱/單位） | `category`, `item_name`, `unit`, `stock_type`, `global_safety_stock`（舊欄，門檻已移到規格層） |
| `inventory_item_variant` | 目錄規格 | `inventory_item_definition_id`, `specification`, `global_safety_stock`（安全庫存量）, `global_threshold`（募資門檻） |
| `location_inventory_safety_stock` | 各據點安全庫存門檻 | `location_id`, `inventory_item_definition_id`, `safety_stock` |
| `supply_item` | **實際庫存批次** | `category/item_name/specification/unit`, `quantity`, `stock_type`, `expiration_date`, `location_id`, `safety_stock`, `image_path`, `is_active` |
| `supply_outbound_log` | 出庫紀錄 | `supply_item_id`, `outbound_quantity`, `recipient_name/contact`, `batch_id`, `recipient_precinct/district/identity`, `is_cancelled/cancelled_at/by/reason`, `operator` |
| `supply_donation_log` | 捐贈紀錄（`donation-create`；獨立捐贈頁已停用，欄位保留） | `supply_item_id`, `donation_quantity`, `donor_name/contact/address/precinct/district/identity`, `operator` |
| `supply_stock_in_log` | 正式入庫來源紀錄（**捐贈主要來源**） | `supply_item_id`, `stock_in_quantity`, `donor_name/contact/address/precinct/district/identity`, `stock_in_time`；捐贈資料可於捐贈紀錄頁後補/編輯/刪除，更新不異動庫存 |
| `supply_disposal_log` | 報廢紀錄 | `supply_item_id`, `disposal_quantity`, `reason`, `operator` |
| `supply_transfer_log` | 轉移紀錄（狀態機） | `batch_id`, `supply_item_id`, `from/to_location_id`, `transfer_quantity`, `status`(Pending/Confirmed/Cancelled), `confirmed_by/at` |
| `supply_adjustment_log` | 庫存盤點調整紀錄（物資明細用） | `supply_item_id`, `quantity_before/after`, `delta`, `reason`, `operator`；寫入/刪除只透過 `stock_adjust`/`stock_adjust_delete` |
| `supply_request` | 缺料「舉手」需求 | `category/item_name/specification`, `requesting_location_id`, `source_location_id`, `quantity`, `status`(Open/Fulfilled/Cancelled), `requested_by` |
| `ai_stock_in_log` | AI 辨識待確認/紀錄 | `input_type`, `input_image_path`, `suggested_*`, `is_confirmed`, `confirmed_supply_item_id` |
| `ai_stock_in_settings` | AI 設定 | `is_enabled`, `provider`, `model`, `api_key`, `api_endpoint`… |
| `line_notification_settings` | LINE 設定 | `is_enabled`, `channel_access_token`, `channel_secret`, 通知條件旗標 |
| `line_bind_codes` / `line_bindings` | LINE 綁定碼 / 已綁定帳號 | `profile_id`, `line_user_id`, `notify_enabled` |
| `notification_state` | 通知去重複簽章 | `key`, `value`(hash) |
| `catalog_synonym` | AI 品項對照同義詞 | `synonym`, `standard_name` |
| `activity_log` | 稽核 Log（誰/何時/做什麼） | `actor_name/role`, `action`, `category`, `target_table/id`, `location_id`, `summary`, `detail`；RLS：檢視限總管、寫入限本人 |
| `password_reset_request` | 忘記密碼申請（**已被自助重設取代，保留**） | `username`, `status`；早期做法 |

> 追加欄位：`inventory_item_definition.sort_order`（庫存種類拖拉排序）、`profiles.password_changed_at`（忘記密碼自助重設時間戳，供總管「近 7 天改過密碼」提示）、`supply_item.created_by/updated_by`（操作人）。

## 二、View（伺服器端彙總，前端一次查詢即可）

| View | 內容 |
|---|---|
| `supply_item_resolved` | 每筆 `supply_item` 解析到對應目錄定義與規格（優先 variant，退回 種類+名稱+規格） |
| `location_low_stock_view` | 據點安全庫存警示：門檻 > 0 **且現有總量介於 1～門檻**（有貨才算，完全沒貨不列入） |
| `global_low_stock_view` | 全系統安全總量警示：同種類/名稱/規格跨據點加總，當「總量 < `global_threshold` × 0.9」列出（觸發點＝門檻×0.9） |
| `donation_source_view` | 捐贈來源統一檢視：物資捐贈 + 物資入庫（有捐贈人）的聯集，供捐贈紀錄/排行/分析共用 |
| `donor_leaderboard_view` | 捐贈者排行（讀 `donation_source_view`，涵蓋捐贈與入庫來源） |
| `recipient_analysis_view` | 領取分析彙總（排除已取消出庫） |
| `dashboard_location_status` | 戰情總覽各據點彙總（**SECURITY DEFINER**，只回統計數字：品項數/總量/低庫存/即期/過期），全角色一致看全部據點 |
| `dashboard_summary` | 戰情總覽四張卡片數字（**SECURITY DEFINER**，只回統計數字），全角色一致 |

> 上述前六支 view 設 `security_invoker = true`（套用查詢者 RLS）。`dashboard_location_status`／`dashboard_summary` 為 `security_invoker = false`（DEFINER）繞過 RLS，但**只回統計數字、不回明細列**，讓戰情總覽對全部角色顯示一致的全域狀態。
>
> **安全庫存單一來源**：低庫存門檻一律來自 `location_inventory_safety_stock`（在「庫存種類設定 → 據點門檻」維護）；物資清單只**唯讀顯示**此門檻，不再寫回。`supply_item.safety_stock` 僅為入庫當下快照，不參與低庫存判斷。

## 三、儲存空間（Storage）

| Bucket | 權限 | 命名 |
|---|---|---|
| `items` | 公開讀取 | ASCII 鍵：`def{定義id}-…-{數量}-{日期}-{序號}.副檔名`；AI 搬入用 `ai{item}-…`、換圖用 `item{id}-…` |
| `ai-stockin` | 私有，路徑第一段＝`auth.uid()` | `{使用者id}/{uuid}.副檔名`（辨識暫存，確認後搬進 items） |

> **中文檔名**：Storage 鍵不收非 ASCII，因此中文命名（`種類-名稱-規格-數量單位-日期序號`）以「下載檔名」呈現（`getPublicUrl(path,{download})` → Content-Disposition），見 `lib/imageUpload.ts`。

## 四、Edge Functions 與 RPC（交易邏輯）

牽涉扣庫存/交易的操作：前端 `functions.invoke()` → Edge Function（驗證角色/據點）→ 以 `service_role` 呼叫 Postgres `SECURITY DEFINER` 函式（真正的交易）。

| Edge Function | 對應 RPC | 動作 |
|---|---|---|
| `outbound-create` | `outbound_create` | 單筆出庫：驗證庫存足夠 → 扣量 → 寫出庫紀錄（手機/LINE 單筆路徑） |
| `outbound-create`（批次） | `outbound_create_batch` | 一位領用人一次多品項，同交易；含分局/鄉鎮/身分別 |
| `outbound-cancel` | `outbound_cancel` | 取消單筆出庫、退回原批次（保留紀錄標記 `is_cancelled`） |
| `donation-create` | `donation_create` | 加量到既有批次 → 寫捐贈紀錄（獨立捐贈頁已停用，保留備用） |
| `disposal-create` | `disposal_create` | 驗證足夠 → 扣量 → 寫報廢紀錄 |
| `transfer-create` | （函式內） | 立刻扣來源庫存、建立 Pending 列（共用 `batch_id`） |
| `transfer-confirm` | `transfer_confirm` | 目的地加量（合併既有同批次，否則新建） |
| `transfer-cancel` | `transfer_cancel` | 退回來源庫存（並還原 `is_active`） |
| `ai-stockin-recognize` | — | 上傳圖 → 呼叫 Vision AI → 解析 → 目錄比對 → 寫 `ai_stock_in_log` |
| `ai-stockin-confirm` | `ai_stockin_confirm` | 合併/新建 `supply_item`、寫紀錄（照片由前端搬進 items） |
| `line-notify` | — | 重算低庫存/即期/過期，比對簽章，變化才推播給已綁定帳號 |
| `line-webhook` | — | LINE 訊息入口：簽章驗證、綁定碼、我的ID |
| `account-admin` | — | 帳號建立/修改/停用（防呆：不能停最後一個 Admin / 自己）、LINE 綁定 |
| `admin-settings` | — | 讀寫 LINE / AI 設定（金鑰不回傳前端） |

> 扣庫存交易的 RPC 皆 `REVOKE` 掉 `anon/authenticated`，只 `GRANT` 給 `service_role`，避免繞過 Edge Function 直接打 `/rpc/`。
>
> **例外**：物資明細的 `stock_adjust` / `stock_adjust_delete`（盤點調整/刪除）自帶 `is_admin()` 檢查，直接 `GRANT` 給 `authenticated` 由前端 `supabase.rpc` 呼叫，不需 Edge Function。`supply_stock_in_log`（入庫來源/捐贈人）與 `supply_request`（舉手）也開放 client 端寫入（RLS 依 `is_admin()`/所屬據點限縮）。

> **`supply_item` 讀取＝全域，寫入＝限縮**：`SELECT` RLS 放寬為所有登入者可讀全部據點（戰情總覽/狀態清單/舉手來源需要跨據點檢視）；`INSERT/UPDATE/DELETE` 仍限總管或所屬據點。前端另在頁面把「操作按鈕」鎖回自己據點（直接操作類如物資明細調整），而「舉手/申請報廢」是送總管審核的請求類功能，總管＋幫主可用、小幫手無。

## 五、資料流範例

**出庫**：`SupplyOutboundCreate` → `invoke('outbound-create')` → 驗證（角色/據點/庫存）→ `rpc('outbound_create')` 交易內扣 `supply_item.quantity`、寫 `supply_outbound_log` → 成功後（可）觸發 `line-notify` → 前端導回 `/outbound` 顯示成功訊息。

**轉移**：建立即扣來源 → 目的地「確認」才入庫（合併同種類/名稱/規格/效期批次）→「取消」退回來源。

**AI 影像入庫**：上傳到 `ai-stockin` → 辨識寫入 `ai_stock_in_log`（待確認）→ 人工核對 → 確認寫入 `supply_item`，前端把照片從 `ai-stockin` 搬到 `items` 並掛到該批次。

**一般入庫**：寫入 `supply_item` 後，同時建立 `supply_stock_in_log`（含捐贈人）。捐贈人可留空，日後於**捐贈紀錄**頁補登/編輯/刪除，只更新來源紀錄、不再增加庫存。

**舉手求援**：狀態清單缺料列「舉手」→ 寫 `supply_request`（需求方=登入據點、來源=物資所在據點）→ 出現在戰情總覽「待處理需求」→「轉移補貨」帶 `?requestId=` 到轉移頁自動帶好來源/目標/品項。

**盤點調整**：物資明細「調整」→ `rpc('stock_adjust')` 修正 `supply_item.quantity` 並寫 `supply_adjustment_log`；「刪除」（限調整列）→ `rpc('stock_adjust_delete')` 回算庫存並刪除該筆。

## 六、機密金鑰放哪

| 金鑰 | 位置 | 說明 |
|---|---|---|
| `VITE_SUPABASE_ANON_KEY` | 前端 build（公開） | publishable 金鑰，受 RLS 保護 |
| `SUPABASE_SERVICE_ROLE_KEY` | Edge Function secrets | 不進前端 |
| OpenAI / Anthropic 金鑰 | `ai_stock_in_settings.api_key`（後台輸入） | 只在 Edge Function 讀取 |
| LINE token / secret | `line_notification_settings`（後台輸入） | 只在 Edge Function 讀取 |

> 這些機密值一律由管理員在 Supabase 後台或系統設定頁輸入，**不寫入前端、不進 git**。
