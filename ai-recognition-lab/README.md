# AI 智慧入庫本機測試

YOLO 建模功能已抽出為 `../modules/vision` 獨立模組。原網址 http://127.0.0.1:5180/yolo 現在提供「照片標註 → 建立模型 → 比較結果」新版介面，原有資料仍保存在本資料夾的 `yolo-data`。獨立啟動、API 及整合方式請讀 [模組操作說明](../modules/vision/README.md)。

這是獨立測試工具，不需要 Supabase、不寫入庫存。照片與描述仍會送到 OpenAI，會使用你的 API 額度。API Key 僅用於本次請求，不保存到檔案或下載報告。

## 啟動

先進入本資料夾執行 `npm install`，再執行 `npm start`，開啟 http://127.0.0.1:5180 。或雙擊「啟動測試.cmd」，會在缺少裁切套件時安裝。需已安裝 Node.js（支援 fetch 的版本）。

## 操作

1. 填入自己的 OpenAI API Key、目前使用的模型與圖片細節。此版只支援 OpenAI。不要把金鑰貼到聊天或報告。
2. 上傳真實 JPG/PNG/WebP 照片。圖片測試先不填文字，避免文字提供正確答案。
3. 替換範例目錄與同義詞為系統實際資料；否則結果不能代表正式系統。
4. 人工清點照片，填入正確答案 JSON。品名為標準品名，每項一筆。只填你確定且要評分的欄位。
5. 同一張照片依序跑 A、B、C，各跑3次；改成下一张照片前先確認這張的答案已保存於報告。
6. 下載報告 JSON。報告包含原始回答、整理結果、正確答案、欄位判分、提示詞、模型、目錄、用量與原始碼雜湊。不包含圖片內容與 API Key。

## 三種版本

- A：直接使用目前後端提示詞、JSON 解析純函式，後處理依目前程式相同規則建立；基準圖片細節依畫面設定。
- B：只提高圖片細節到 high；提示詞與後處理不變。請以相同模型比較A、B。
- C：圖片細節與A相同；補充完整目錄與不猜測規則、逐項信心值，後處理改成目錄類別/單位優先，未知數量保留 null。C是整組規則改善，若有效，再分拆提示詞與後處理個別測試。

先挑10至20張照片，包含單品、多品、重疊、包裝小字、模糊、非物資、空場景。用真實照片，不用生成圖片驗證辨識率。保留另一批未參與調整的照片，最後驗證是否仍有效。

品名精確率=正確品名數/預測品項數；召回率=正確品名數/答案品項數。欄位分數包括漏辨識，漏掉的品項算錯；額外項目會降低品名精確率。相同品名出現多筆時按順序配對，若同名不同規格，請分開拍攝測試或人工核對報告，避免配對影響分數。

尚未用真實API測試前，不可宣稱辨識率已提升。此工具只驗證辨識；不涵蓋權限、照片儲存、核對下拉選單或入庫交易。只改本工具不會改變正式網站。

## D 組合辨識與模型選用

簡易物件：單品、少量、包裝清楚。使用「簡易辨識模型」及基準細節。複雜物件：多品項、重疊或小字。使用「複雜辨識模型」及 high 細節。難度由操作者選擇，不會自動判斷。各階段模型名稱均可自訂；預設相同是為了先比較方法，不宣稱預設模型最準。

流程：定位物資/標籤（最多4框）→ sharp裁切原圖 → 視覺模型讀取包裝文字 → 整圖及局部一起辨識 → 可選另一模型複核 → 目錄單位及分類核對 → 正確答案判分。每一階段可單獨開關，D最多4次API請求。此版文字辨識是多模態模型讀字，不是獨立OCR引擎。

局部圖片可在頁面預覽；圖片先依EXIF轉正，保持定位與裁切座標一致。局部只提供標籤資訊，不當作額外物品。自動定位仍可能裁錯，務必核對裁切預覽。定位、文字讀取或複核失敗會降級並回報警告；主要辨識失敗則整次測試失敗。

下載報告保存每階段原始回答、實際模型、用量、耗時、裁切座標與警告，不保存圖片或金鑰。每次複核可以觀察完整效果；「僅不確定時」由未知數量、目錄外品名或低信心啟發式觸發，不保證找出所有錯誤。沒有圖片時跳過定位及讀字。

C/D移除原版「不確定填1」規則，改成未知填null；測試時人工答案不會送進任何模型。建議先A對D，再關閉D中的單一階段，確認效果來自哪裡。當兩模式都使用相同模型時，測的是方法；比較不同模型需固定方法。

完整離線測試：本資料夾執行 `npm test`。需要真實照片與你的API Key才能測實際準確率。

離線驗證：`node --test ai-recognition-lab/core.test.mjs`
